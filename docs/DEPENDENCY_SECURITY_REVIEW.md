# Dependency security review — Phase 9B.1

Audit dates: 2026-07-25. The baseline `npm.cmd audit --omit=dev --json` reported **12 high / 1 moderate** findings. After the supported remediation below, the same command reports **6 high / 1 moderate** findings (245 production packages). The full installation audit is intentionally broader because it includes build and test tooling.

Phase 9B.1 refresh recheck: Next `16.2.12`, OpenNext Cloudflare `1.20.2`, Prisma `7.9.0`, Wrangler `4.114.0`, and `pg` `8.22.0` remain current for their declared compatible ranges. No `@neondatabase/serverless` package is installed; application database access uses `pg` through `@prisma/adapter-pg`. Better Auth and its Prisma adapter were updated from `1.6.24` to compatible `1.6.25`, and `eslint-config-next` now matches Next `16.2.12`. The fresh production audit remains 6 high / 1 moderate; no unsupported remediation was applied.

## Remediation performed

- Updated pinned Next from `16.2.11` to the compatible patch `16.2.12`. The audit still includes it, so this is a supported maintenance patch, not a claimed advisory fix.
- Moved the unchanged, exact `@opennextjs/cloudflare@1.20.2` from `dependencies` to `devDependencies`. It is imported only by build/development configuration and invoked by `cloud:build`; it is not application request code. This removes its six inherited findings from the production audit without an override, suppression, downgrade, or lockfile edit.
- Added `dependency:separation:verify`. It guards package placement; excludes OpenNext, AWS CDK, test, local-DB and Prisma CLI tooling from application runtime declarations/source; rejects unsafe dynamic package loading and process spawning in `src`; checks client/server boundaries, secret-free Worker config, no R2 staging binding, and no development server/tooling in the container runtime. It is static source/package evidence only and does **not** prove a Linux Worker artifact.

No `npm audit fix`, force fix, major downgrade, override, or advisory suppression was used. The offered `@opennextjs/cloudflare@0.2.1`, `prisma@7.8.0`, and `next@14.2.35` fixes are breaking/downgrade paths and were rejected.

## Exact fictional-staging release gate

`free-preview-cloudflare-neon` remains fictional-only and no-deploy by default. It is **blocked** until a later authorized Linux session produces and reviews the actual `.open-next/worker.js` artifact, passes `cloud:bundle:verify` against that artifact, and shows that no runtime-reachable high advisory remains. It must also rerun this production audit; pass `dependency:separation:verify`, `cloud:runtime:verify`, client-secret/data-boundary checks and the full regression suite; review whether CI builds untrusted repository input; and obtain the separate deployment confirmation. R2 is absent from fictional staging, PostgreSQL/Neon remains the only planned database, and `production-secure-aws` remains optional and undeployed.

This review expires on the next dependency change, OpenNext/Next/Prisma release, CI trust-model change, or any proposed staging release—whichever occurs first.
